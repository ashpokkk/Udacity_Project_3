Scroll down past build_orchestrator_agent(). It’s the last Phase 1 function, and it ends with return Agent(...).
Find the header # TASK 3 - AGENTCORE DEPLOYMENT + GUARDRAILS. Right under it you’ll see the old create_guardrail() and deploy_to_agentcore_runtime(), both ending in pass.

Replace it all with the contents of phase2_functions.pyPHASE 1 - ISSUES AND FIXES

1. DNS / network error when running demo.py
   Problem: config.py could not reach AWS (sts.us-east-1.amazonaws.com).
   Fix: restored the internet connection and ran the command again.

2. Order and customer "not found"
   Problem: the DynamoDB orders and customers tables were empty.
   Fix: ran python infrastructure/seed_data.py (4 customers, 16 orders loaded).

3. AccessDenied error (expired AWS lab session)
   Problem: the lab session expired, so AWS blocked the old credentials.
   Fix: restarted the lab and logged in again with fresh credentials.

4. Order ORD-27176 not in the seeded data
   Problem: demo.py and the test command use ORD-27176, but it does not exist
   in the orders table. Real orders for CUST-001 include ORD-20723.
   Result: the order routing was verified with ORD-20723 instead.
   To revisit before Phase 4 (Scenario A).

5. Math answer rounded too early in one chat run
   Problem: one chat run gave $134.95 instead of $134.96.
   Result: routing was correct (CommunicationAgent only). The test command
   gave the correct $134.96.
   To revisit in Phase 4 (Scenario C).

6. Policy answers were empty
   Reason: the Knowledge Bases are created in Phase 3, so the KB IDs are blank.
   Routing through PolicyAgent and the 3 parallel retrievers was verified.
